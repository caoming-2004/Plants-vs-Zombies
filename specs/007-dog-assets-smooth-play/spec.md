# Feature Specification: 狗狗素材与流畅可玩体验

**Created**: 2026-10-28  
**Status**: Draft  
**Input**: 用户提供小宝、小杜、好孩子三张高清动作图，要求统一地图中狗狗尺寸、完整展示、动作和开始界面切换流畅，并尽快交付可玩版本、精简测试和清理测试产物。

## User Scenarios & Testing

### User Story 1 - 使用三只指定狗狗进行游戏 (Priority: P1)

玩家在游戏中看到与名字对应的小宝、小杜、好孩子，三只狗在地图上的视觉尺寸接近，任何动作都能看到完整身体。

**Independent Test**: 分别让三只狗出现在地图各行、边缘和相邻位置，逐一播放其现有动作并截图核对。

**Acceptance Scenarios**:

1. **Given** 三张用户提供的图片可读取，**When** 玩家看到任一狗狗，**Then** 名字、形象与对应图片一致，没有混用其他狗的素材。
2. **Given** 不同狗狗同时出现在地图中，**When** 比较其站立姿态的可见高度，**Then** 最大值与最小值之比不超过 1.15，且头、尾、四肢完整可见。
3. **Given** 狗狗处在相邻位置或地图边缘，**When** 动作播放，**Then** 允许彼此轻微重叠，但不得因裁切、界面遮挡或地图边界丢失身体部位。

### User Story 2 - 流畅进入并完成一局 (Priority: P1)

玩家点击开始按钮后及时看到游戏画面，狗狗动作连续，能够完成既有核心玩法和重新开始。

**Independent Test**: 从启动界面点击开始，完成一局并重新开始；观察切换时间、动画停顿和玩法反馈。

**Acceptance Scenarios**:

1. **Given** 开始界面已显示，**When** 玩家按下开始按钮，**Then** 100 毫秒内出现可见反馈，游戏画面在 1 秒内可操作，切换过程没有明显长时间冻结。
2. **Given** 三只狗狗在同一对局中活动，**When** 播放待机及其他既有动作，**Then** 动作顺序连续、没有闪白或明显卡帧，输入仍能及时响应。
3. **Given** 玩家完成一局，**When** 重新开始，**Then** 资源、敌人和胜负状态按既有规则重置，仍可继续游玩。

### User Story 3 - 快速获得精简的可玩版本 (Priority: P2)

开发者只运行足以确认本次体验和核心玩法的检查，测试结束后项目中不留临时测试可执行文件和压缩包。

**Independent Test**: 检查交付记录和项目文件，确认一次针对性试玩与必要回归检查有结果，临时测试产物已清理。

**Acceptance Scenarios**:

1. **Given** 本轮修改完成，**When** 验证可玩性，**Then** 检查开始、三只狗狗、核心循环和重新开始，记录执行结果与未验证项。
2. **Given** 测试结束，**When** 检查项目，**Then** 本轮生成的临时测试 EXE 与 ZIP 均已删除，正式交付物不被误删。

### Edge Cases

- 原始动作图的背景或透明度不一致时，游戏中不得出现棋盘格、白色矩形或明显边缘光晕。
- 不同动作姿态高度变化时，以角色统一的站立基准控制尺寸；抬爪、趴卧仍须完整显示。
- 同屏狗狗较多、窗口缩放或首次点击开始时，仍应满足切换和动画要求。
- 图片缺失或无法读取时，应明确报告受阻，不得悄悄替换身份。

## Requirements

### Functional Requirements

- **FR-001**: 游戏 MUST 使用用户提供的 `小宝.png`、`小杜.png`、`好孩子.png` 作为三只同名狗狗的形象来源，保留各自可辨认特征及已有必要动作。
- **FR-002**: 地图中三只狗狗的站立姿态可见高度最大值与最小值之比 MUST ≤1.15；不同动作可自然改变姿态，不得通过裁切躯体强行统一大小。
- **FR-003**: 狗狗在地图边缘、相邻位置和动作过程中 MUST 完整展示头、尾与四肢；允许轻微互相重叠，但主要轮廓和身份仍须清楚。
- **FR-004**: 狗狗动画 MUST 连续播放既有动作，避免跳帧、停顿、闪白及素材背景露出；动作期间输入和玩法更新不得被阻塞。
- **FR-005**: 按下开始按钮后 MUST 在 100 毫秒内给出可见反馈，并在 1 秒内进入可操作的游戏画面；首次进入和重新开始均适用。计时从鼠标按下事件进入游戏事件循环开始，到显示可操作画面并能够接收一次有效游戏输入为止。
- **FR-006**: 本轮改动 MUST 保持现有阳光、种植、敌人推进、胜负及重新开始的核心循环可用。
- **FR-007**: 验证 MUST 以一次针对性试玩和受影响核心循环的必要回归为主；避免重复、无关或大规模性能测试。失败或未执行的检查须如实记录。
- **FR-008**: 测试完成后 MUST 删除本轮产生的临时测试 EXE 和 ZIP；正式发布版本和用户原有文件不得因此被删除。

### Key Entities

- **狗狗角色**：名称、对应来源图片、站立尺寸基准和现有动作集合。
- **测试产物**：本轮为验证而生成、可识别来源的临时 EXE 与 ZIP。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 三只狗狗在地图中均身份正确；站立高度比≤1.15；边缘、相邻和动作姿态检查中身体完整率为 100%。
- **SC-002**: 连续 10 次开始界面点击均在按下事件处理后 100 毫秒内出现可见反馈，且从按下事件进入游戏事件循环到显示可操作画面并能接收有效游戏输入不超过 1 秒；首次进入和重新开始各至少覆盖一次。
- **SC-003**: 一次完整试玩中三只狗狗的既有动作无可见闪白、长停顿或背景露出，核心循环可完成并可重新开始。
- **SC-004**: 本轮临时测试 EXE 和 ZIP 在验证结束后剩余数量为 0；验证记录列明实际执行的最小检查及结果。

## Assumptions

- 三张附件是本轮三只狗狗形象的权威来源；图片内动作格可用于角色动画。
- “大小相差不大”按站立姿态高度差不超过 15% 验收；趴卧姿态不与站立高度直接比较。
- “卡帧感”以真实窗口中的连续视觉检查为主，不要求为本轮新增全面性能基准或大量自动化测试。
- 本次命令产出规格；实现、试玩和清理测试产物在后续实施阶段执行。
