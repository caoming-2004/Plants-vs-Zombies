# Feature Specification: 波次界面修复、通关报错与高清可切换背景

**Feature Branch**: `013-wave-hud-error-backgrounds`

**Created**: 2026-10-31

**Status**: Draft

**Input**: User description: "优化以下内容：1、游戏内第几波样式的字体挡住了地图；2、通关第一关之后报错；3、游戏背景画质太低了，可以联网或生图使得背景清晰，可以出一个换背景的功能。"

## Clarifications

### Session 2026-10-31

- Q: 波次、下一波预告和关卡名称放在哪里最合适？ → A: 统一放在顶部 HUD 状态区，完全避开 5×12 草坪。
- Q: 玩家选择的背景是否需要在关闭游戏后保留？ → A: 本机保存，下次启动自动恢复；资源缺失时回退默认背景。
- Q: 三套高清背景采用哪种风格组合？ → A: 日间草坪、夜间草坪、黄昏草坪。
- Q: 高清背景素材如何获取和交付？ → A: 开发阶段联网获取或本地生成，最终随安装包离线提供。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 波次与关卡文字不再遮挡草坪 (Priority: P1)

玩家在对局中查看“第几波”、下一波预告和关卡名称时，这些信息只出现在顶部 HUD 状态区，不再覆盖草坪格子、植物、僵尸、阳光或割草机。第 1 行到第 5 行、第 1 列到第 12 列始终完整可玩，玩家不会因为文字挡住了目标而点错或看不清战场。

**Why this priority**: 波次信息是每局都会显示的核心状态，直接压在地图上会遮挡玩家需要观察和点击的对象，属于影响操作与胜负判断的界面缺陷；必须先修复。

**Independent Test**: 在 1050×600 逻辑画布和 1920×1080 等常见窗口尺寸下，分别检查第 1 波开始前、波次进行中、最后一波前和窗口缩放后的画面；确认所有波次/关卡文字均在顶部 HUD 状态区，不覆盖草坪格子、角色、阳光和主要按钮，且文字本身不被裁切。

**Acceptance Scenarios**:

1. **Given** 玩家处于任意关卡的对局中，**When** 画面显示当前波次、下一波预告或关卡名称，**Then** 这些文字完全位于顶部 HUD 状态区，不覆盖 5×12 草坪格、植物、僵尸、阳光、割草机和操作按钮。
2. **Given** 窗口为 1050×600 或 1920×1080，**When** 玩家查看波次信息，**Then** 文字完整可读、不被裁切、不与卡片/暂停按钮/结算面板重叠；窗口缩放后仍保持不遮挡。
3. **Given** 波次即将开始或正在进行，**When** 玩家观察预告内容，**Then** 预告在波次开始前适当提前出现，类型、数量和主要行与实际出怪一致；波次切换后不残留旧预告。
4. **Given** 关卡名称较长或为“最后一波”等文本，**When** 显示在状态区，**Then** 使用固定安全区域或换行/缩写，不越界到可玩草坪。

---

### User Story 2 - 通关第一关后流程稳定 (Priority: P1)

玩家清除第一关最后一只僵尸后，看到正常的胜利结算，不会遇到报错、卡死或错误弹窗；可以继续下一关、重玩第一关或返回主菜单，进度和星级被正确保存，重新启动后第二关仍然可用。

**Why this priority**: 通关后的流程是玩家必经路径；出现报错会直接中断体验并造成进度不可信，必须先于背景美化解决。

**Independent Test**: 连续完成至少 20 次第一关通关，分别点击“下一关”“再玩一局”“返回主菜单”“退出”；检查每次是否出现异常、结算是否只触发一次、第二关是否正确解锁、重启后进度是否保留；再模拟进度文件不可写或损坏，确认不会崩溃。

**Acceptance Scenarios**:

1. **Given** 第一关最后一只僵尸被清除，**When** 进入胜利结算，**Then** 游戏显示结算界面且没有未处理异常、错误弹窗或进程退出；玩家仍可操作鼠标/键盘。
2. **Given** 胜利结算已显示，**When** 玩家选择“下一关”，**Then** 第二关以正确初始状态开始，植物、僵尸、阳光、冷却和波次均不继承上一局；选择“再玩一局”则第一关完整重置。
3. **Given** 第一关已通关，**When** 玩家返回主菜单并重新启动应用，**Then** 第二关保持解锁，第一关的最佳星级/时间仍保留，重复通关不会重复解锁或损坏进度。
4. **Given** 结算保存进度失败、进度文件损坏或第二关资源缺失，**When** 玩家继续操作，**Then** 游戏给出可理解的提示并保持可返回主菜单/重试，不得崩溃或静默卡死。

---

### User Story 3 - 高清且可切换的背景 (Priority: P2)

玩家看到更清晰、细节更丰富、具有真实感和高级感的草坪背景；可以从主菜单更换背景，至少有三套高清背景可选（日间草坪、夜间草坪、黄昏草坪），切换后立即生效并在下次启动时保留。背景只改变视觉，不影响草坪格子、植物、僵尸、阳光和界面的可读性。

**Why this priority**: 背景是玩家持续观看的画面基础，当前画质偏低影响整体观感；在修复遮挡和通关报错之后，再用高清素材和切换功能提升视觉体验。它不改变玩法，因此优先级低于两个 P1 缺陷。

**Independent Test**: 在主菜单打开背景选择，逐一预览并切换至少三套背景；在 1050×600 和 1920×1080 窗口检查清晰度、边缘细节和界面可读性；重启应用确认选择保留；移除或破坏当前背景资源后启动，确认回退且不崩溃。

**Acceptance Scenarios**:

1. **Given** 玩家首次进入游戏，**When** 查看默认草坪，**Then** 默认背景使用高清素材，在 1050×600 和 1920×1080 下不出现明显模糊、放大锯齿或色块。
2. **Given** 玩家在主菜单打开“更换背景”，**When** 浏览选项，**Then** 至少有三套可辨认的高清背景，当前选择有明确标记，并显示缩略图/名称。
3. **Given** 玩家选择另一套背景，**When** 返回菜单或开始游戏，**Then** 新背景立即生效且只改变视觉；草坪格子、角色、阳光、HUD 和按钮的可读性不下降。
4. **Given** 玩家重启应用，**When** 再次进入菜单或关卡，**Then** 上次选择的背景被恢复；如果该背景文件缺失或损坏，自动回退到可用的默认背景并提示。
5. **Given** 应用离线运行，**When** 玩家切换背景或开始游戏，**Then** 所有背景资源已随包提供，不依赖网络下载；图片细节和清晰度不因离线下降。

---

### Edge Cases

- 波次名称较长、出现“最后一波”、下一波在 1 秒内开始或同一帧切换波次时，状态区文字仍不得进入草坪或与卡片/暂停按钮重叠。
- 窗口从 1050×600 放大到 1920×1080、超高分辨率或窄屏/非 16:9 比例时，波次文字、预告面板和关卡名不得被裁切或重新覆盖地图。
- 第一关在割草机已消耗、星级未全部达成、阳光/植物剩余、快速连续点击“下一关/重试”的情况下通关，结算和进度仍只结算一次，不出现重复解锁或重复保存。
- 进度文件只读、磁盘空间不足、保存中途关闭应用、第二关 JSON 损坏或旧版本存档格式不匹配时，不得崩溃；应提示并允许返回菜单或重试。
- 背景文件缺失、损坏、分辨率过低、色彩空间异常或内存不足时，回退到默认背景且不阻塞进入游戏。
- 玩家在游戏中快速连续切换背景、在对局中打开背景选择、切换后立即暂停/退出/重开时，不得出现旧背景残影、黑屏或布局跳动。
- 背景对比度、亮度和细节不得让僵尸、阳光、植物或状态文字难以辨认；夜间/高饱和背景也不得改变可玩区域边界。
- 背景资源来自联网下载或本地生成时，来源、授权和随包文件必须可追溯；运行时不得依赖网络。

## Requirements *(mandatory)*

### Functional Requirements

**波次界面**

- **FR-001**: 当前波次、下一波预告、关卡名称和波次提示 MUST 位于顶部 HUD 状态区，不得覆盖 5×12 草坪格、植物、僵尸、阳光、割草机、操作按钮或结算面板。
- **FR-002**: 波次/关卡文字 MUST 在 1050×600 和 1920×1080 等常见窗口尺寸下完整可读、不被裁切、不与 HUD 控件重叠；窗口缩放后仍保持。
- **FR-003**: 波次预告 MUST 在波次开始前适当提前出现，内容与实际敌人类型、数量和主要行一致；波次切换后不得残留旧预告或旧关卡名。
- **FR-004**: 长波次名称、最后一波、预告倒计时和关卡名 MUST 使用固定安全区域或换行/缩写策略，不得越界进入可玩草坪。

**通关流程**

- **FR-005**: 清除第一关最后一只僵尸后，游戏 MUST 正常进入胜利结算，不得出现未处理异常、错误弹窗、卡死或进程退出。
- **FR-006**: 结算页的“下一关”“再玩一局”“返回主菜单”“退出”MUST 均可正常使用；进入下一关或重试时 MUST 使用对应关卡的完整初始状态，不继承上一局植物、僵尸、阳光、冷却或波次。
- **FR-007**: 第一关通关后 MUST 解锁第二关并保存进度；重新启动后解锁状态、最佳星级和最佳时间 MUST 保留；同一次通关不得重复解锁或重复写入。
- **FR-008**: 进度保存失败、进度文件损坏/只读、第二关资源缺失或结算渲染异常时，系统 MUST 给出可理解提示并保持可返回菜单/重试，不得崩溃或静默卡死。
- **FR-009**: 现有 5 关战役、星级、无尽模式、暂停、重开、返回菜单和狗狗外观 MUST 保持可用；本次修复不得改变玩法数值或关卡规则。

**高清背景与切换**

- **FR-010**: 默认草坪背景 MUST 使用真实感/高级感的高清素材（授权摄影或写实渲染，不得使用幼稚卡通/低龄插画），源图至少 2560×1440；在 1050×600 和 1920×1080 下不得出现明显放大模糊、锯齿或色块，且完整覆盖草坪区域。
- **FR-011**: 游戏 MUST 提供至少三套可辨认的高清背景选项（日间草坪、夜间草坪、黄昏草坪），并从主菜单提供“更换背景”入口；每套背景显示名称和缩略图，当前选择有明确标记。
- **FR-012**: 玩家选择背景后 MUST 立即应用，不得要求重开游戏；选择 MUST 在本机保存并在下次启动时恢复。
- **FR-013**: 当前背景文件缺失、损坏或不可读时，系统 MUST 自动回退到可用默认背景并给出提示，不得阻止进入游戏。
- **FR-014**: 背景 MUST 只改变视觉表现，不得改变草坪格尺寸/位置、角色碰撞、点击区域、HUD 布局或玩法结算；背景与文字/角色之间保持足够对比度。
- **FR-015**: 所有背景资源 MUST 随安装包提供，运行时不得依赖网络；使用联网获取或本地生成素材时，来源、授权和派生记录 MUST 可追溯。
- **FR-016**: 背景加载和切换 MUST 不造成明显卡顿；标准对局和菜单切换后仍满足现有性能门槛，切换失败不得影响正在进行的对局。

### Key Entities *(include if feature involves data)*

- **波次状态显示**: 当前波次、下一波名称/数量/主要行、预告倒计时、关卡名称及其安全显示区域。
- **关卡结算状态**: 第一关胜利、星级、最佳时间、下一关解锁结果、进度保存状态和错误回退状态。
- **背景选项**: 背景 ID、名称、缩略图、源图分辨率、文件完整性、来源/授权记录和当前选择。
- **背景偏好**: 玩家最近选择的本机背景 ID；写入 progress 的独立 `settings` 字段，与关卡进度数据分开管理，可回退默认值。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在 1050×600 和 1920×1080 下，波次/关卡文字覆盖草坪格、植物、僵尸、阳光、割草机或操作控件的次数为 0；文字被裁切或与 HUD 重叠的次数为 0。
- **SC-002**: 连续完成第一关 20 次，胜利结算出现未处理异常/错误弹窗/进程退出的次数为 0；“下一关/再玩一局/返回主菜单/退出”操作成功率为 100%。
- **SC-003**: 第一关通关后第二关解锁率 100%；重启后解锁和最佳星级/时间保留率 100%；同一局重复解锁或重复保存次数为 0；损坏进度/只读进度导致的崩溃次数为 0。
- **SC-004**: 默认背景源图分辨率不低于 2560×1440，且人工评审确认呈现真实感/高级感、不是幼稚卡通；在 1920×1080 窗口下，背景区域出现明显放大模糊或可见像素块的抽样检查次数为 0。
- **SC-005**: 至少提供日间/夜间/黄昏 3 套在主题、名称和缩略图上明显不同的高清背景；背景选择应用时间不超过 1 秒，重启后选择保留率 100%，缺失/损坏背景回退成功率 100%。
- **SC-006**: 切换背景前后，草坪格位置/尺寸、植物/僵尸点击区域、HUD 布局和胜负结果差异为 0；标准对局平均帧率不低于 58 帧/秒、95% 帧间隔不超过 18 毫秒。
- **SC-007**: 运行时背景加载与切换产生的网络请求次数为 0；每套背景的来源、授权和随包文件可追溯率 100%。
- **SC-008**: 现有 5 关战役、星级、无尽、暂停/重开/菜单和狗狗外观回归检查通过率 100%，玩法数值未改变。
- **SC-009**: 下一波预告与实际出怪在敌人类型、数量和主要行上的一致率为 100%，且至少提前 2 秒出现；波次切换后旧预告/旧关卡名残留次数为 0。

## Assumptions

- “第几波样式的字体挡住了地图”按所有波次/关卡状态文字理解，包括当前波次、下一波预告、关卡名称和波次提示；修复原则是移入 HUD/安全区，而不是把文字缩小到难以阅读或继续压在地图上。
- “通关第一关之后报错”发生在 Windows 桌面版的结算/下一关流程；用户未提供具体错误文本，因此本次以“整个结算与后续操作不出现未处理异常、进度可恢复”为验收目标，具体根因在方案阶段定位并修复。
- 允许在开发阶段联网获取或本地生成背景素材，但游戏运行时必须完全离线；所有背景随安装包提供，不提供运行时下载或用户上传。
- 高清背景采用真实感摄影或写实渲染的高级感图像（允许开发阶段联网检索授权照片或本地生成），不使用幼稚卡通/低龄插画；提供日间、夜间、黄昏三种光照主题，至少 3 套；不改变 1050×600 逻辑画布、五行十二列或现有角色尺寸。
- 背景选择作为本机视觉偏好写入 progress 的独立 `settings` 字段，与关卡进度数据分开管理；外观选择继续保持当前“仅本次运行内有效”的行为。背景和外观互不影响。
- 本次只验收 Windows 桌面版；安卓安装、触控和性能验收不在本轮范围。
- 现有第一关的数值、波次、星级目标和狗狗素材保持不变；背景替换和 HUD 调整不得改变通关条件。
