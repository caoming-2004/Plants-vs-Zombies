# Contract: 第一关结算与错误恢复

**Feature**: `013-wave-hud-error-backgrounds` | **Date**: 2026-10-31

## 流程

```text
playing（day_01）
  -> 最后一只僵尸死亡
  -> won
  -> 只记录一次 progress（stars/ticks/unlock day_02）
  -> 显示结算（无未处理异常）
  -> 下一关 / 再玩一局 / 返回主菜单 / 退出
```

## 结果状态

- 使用 `session_id` 与 `recorded_session` 防止重复保存；同一局结算多次进入不得重复解锁/写入。
- 下一关必须创建新的完整 `Simulation` 状态（植物/僵尸/阳光/冷却/波次归零）。
- 重试当前关必须完全重置，不继承上一局任何实体或进度。
- 返回主菜单后再次进入第一关，仍可正常通关并更新最佳星级/时间。

## 错误处理

- 结算/进度/下一关加载任一环节抛出异常时：记录完整 traceback（本机日志）；在界面显示可理解提示；保留“返回主菜单/重试”操作；不得出现未处理异常弹窗或卡死。
- 进度文件只读/损坏/版本不匹配：读取回退默认/保留可用字段；保存失败只提示，不影响本局结算显示。
- 第二关 JSON 缺失/损坏：提示并允许返回主菜单；不得让进程退出。
- 错误提示不得覆盖结算主要按钮的可点击区域。

## 兼容性

- `Simulation`、`Command`、`snapshot` 和事件 schema 不变；错误处理只在 app/progress 边界。
- 现有 5 关、星级、无尽、狗狗外观、暂停/重开/菜单保持可用。
- 结算页按钮位置和命中区域保持现有布局；新增逻辑不得引入重复点击竞态。

## 验收

1. 无头 harness 连续 20 次“第一关清空→结算→下一关/重试/返回/退出”：未处理异常 0、错误弹窗 0、day_02 解锁 100%、重复保存 0。
2. 只读 progress、损坏 progress、缺失 day_02：均显示提示且可返回菜单/重试。
3. 真实窗口通关一次，验证结算、下一关、重启后 day_02 仍解锁。
