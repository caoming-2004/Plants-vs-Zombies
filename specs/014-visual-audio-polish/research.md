# Research: 字体、场景背景与游戏音乐优化

## Decisions

### 复用现有 Pygame 文字渲染和窗口合成路径

- **Decision**: 保持 `pygame.font.Font` 的统一文字入口和缓存，在现有 1050×600 画布到窗口的最终呈现处改进放大质量；只在发现确有字符覆盖缺口时才处理字体资源。
- **Rationale**: 项目已有 Noto Sans SC、抗锯齿渲染及文字表面缓存。最终窗口当前通过普通缩放放大，先修正这个共同链路比替换字体或逐个界面重写更小、更一致。
- **Alternatives considered**: 改用另一套字体；把整个逻辑画布升级为高分辨率。前者未证明能解决放大链路问题，后者扩大性能和坐标修改范围。

### 更新既有背景选项而非另造背景选择系统

- **Decision**: 使用授权给本项目的图像生成能力产出一套成熟写实的场景主素材，再沿用本地背景构建流程生成日间、夜间、黄昏三个一致变体；沿用 BackgroundCatalog、manifest、缩略图、持久化选择及回退。
- **Rationale**: 现有三项来自同一张泛草坪照片，且已建立清单/校验/选取流程；新素材应契合庭院防守战场，同时保留既有偏好和 UI。
- **Alternatives considered**: 只更换日间默认而保留其余旧背景；删除背景选择。前者留下不符合场景的选项，后者会破坏用户已有能力。

### 复用 pygame-ce 音频，不增加依赖

- **Decision**: 添加一个 presentation 层音乐状态控制器，使用现有 pygame-ce 音频能力；主菜单和对局播放本地循环音乐，暂停/结算按状态暂停或停止，胜利只触发一次短提示。
- **Rationale**: 游戏已依赖 pygame-ce，设置和播放状态只涉及单人本地游戏，无需网络服务或新的音频库。
- **Alternatives considered**: 外部播放器或在线流媒体；它们增加依赖、运行环境和离线失败面。

### 音乐设置扩展到现有本机设置区

- **Decision**: 在 `settings` 下保存音乐启用/音量，不升级整个进度数据模型；v1/v2 存档缺字段时使用默认音乐设置，保存时保留已有设置。
- **Rationale**: `Progress` 已经负责持久化视觉偏好并对缺少设置字段进行迁移，音乐偏好属于同一玩家本机偏好。
- **Alternatives considered**: 单独配置文件；会引入额外的一致性和备份行为。

### 离线且授权可追溯的素材

- **Decision**: 背景使用本项目生成的成熟写实场景；音乐素材只选来源和分发许可明确、可随包离线使用的曲目；个人/狗狗声音只在素材由用户提供或授权后使用。
- **Rationale**: 安装包离线可用，素材权利可查，未授权个人声音不会被假定可用。
- **Alternatives considered**: 运行时下载、许可不明素材、未经授权的声音克隆；均不满足规格约束。

## Implementation Notes

- 资产全部进入 `assets/`，Windows PyInstaller spec 已整体打包该目录，发布附属文件步骤继续保留字体许可证并增补必要音乐来源信息。
- 背景 manifest 现要求分辨率、哈希、来源和许可；生成素材填写生成方式/工具记录，而不是伪造外部摄影署名。
- 不运行全量测试。只检查进度设置兼容、背景清单与渲染、音乐状态切换、标准窗口帧率，以及一次 Windows 目录包的可玩路径。
