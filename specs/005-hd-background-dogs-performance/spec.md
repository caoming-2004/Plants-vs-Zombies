# Feature Specification: 高清背景、狗狗素材与运行流畅度

**Feature Branch**: `version1`  
**Created**: 2026-10-26  
**Status**: Draft  
**Input**: 用户要求联网寻找更清晰的背景；重新上传小宝、小杜照片并新增“好孩子”照片；缩小狗狗以减少植物之间的重合；解决实际游戏卡顿。

## Clarifications

### Session 2026-10-26

- Q: 新背景应沿用当前草坪的房屋、道路和种植格布局，还是可以重新设计场景构图？ → A: 保留现有布局，仅提升清晰度和细节。
- Q: 流畅度验收应以你当前这台电脑运行打包后的游戏为准，还是要求其他电脑也达到相同指标？ → A: 以当前电脑运行的打包游戏为准。
- Q: 新上传的狗狗照片应作为卡通角色的外形参考，还是直接把照片主体放进游戏画面？ → A: 两者都要；进入游戏前可在外观选择中选照片版或生成的卡通版。
- Q: 选择“照片版”后，狗狗在对局中也需要完整播放行走、攻击和受击等动作吗？ → A: 照片版和卡通版都播放完整动作。
- Q: 只上传小宝、小杜和好孩子的照片时，照片版里被窝和嗷嗷嗷应如何显示？ → A: 两只沿用现有卡通造型；被窝使用最初的灰白毛造型。项目中该造型的原始动作表为 `assets/skins/dogs/source/beiwo-sheet.png`。

## User Scenarios & Testing

### User Story 1 - 清晰且可辨认的草坪背景 (Priority: P1)

玩家在常用窗口尺寸下看到清晰、风格协调的草坪，仍能一眼认出种植格、行列边界、角色和可收集物。

**Why this priority**: 背景占据大部分画面，低清晰度持续影响视觉体验。

**Independent Test**: 在1050×600、1260×720、1920×1080保存相同场景的新旧画面，以原始像素尺寸并排检查房屋边缘、草坪格线和道路纹理；记录每处是否出现可见块状模糊、拉伸或断裂，并检查角色对比度。

**Acceptance Scenarios**:

1. **Given** 玩家进入白天关卡，**When** 以1050×600、1260×720或1920×1080窗口查看草坪，**Then** 背景不出现明显块状模糊、拉伸变形或断裂边缘，种植格仍可辨认。
2. **Given** 新背景被采用，**When** 玩家选择植物、拖放或收集阳光，**Then** 背景不会遮盖交互反馈，也不会改变可操作区域。
3. **Given** 背景来自网络，**When** 游戏离线启动，**Then** 已选背景仍能正常显示，并能查到其来源及使用许可记录。

---

### User Story 2 - 用新照片更新狗狗并减少遮挡 (Priority: P1)

玩家提供小宝、小杜和好孩子的照片后，在进入游戏前可选择照片版或依据照片生成的卡通版；两种外观中都能辨认这些狗，草坪上的狗狗完整可见，邻近植物的主要身体部分不被大片遮挡。

**Why this priority**: 角色辨识与相邻格清晰度直接影响用户最关心的个性化画面。

**Independent Test**: 用三只狗的新照片核对角色特征，检查卡片、预览、拖动、草坪和动作中的完整性；在相邻格与相邻行密集摆放时检查遮挡。

**Acceptance Scenarios**:

1. **Given** 三只狗的新照片可用，**When** 玩家在进入游戏前选择照片版或卡通版狗狗外观，**Then** 小宝、小杜及好孩子的可见造型分别保留照片中可辨认的主要特征，身份不会混淆。
2. **Given** 两个植物位于相邻格或相邻行，**When** 它们播放最大姿态动作，**Then** 每只狗的头部及主要身体轮廓仍可辨认；边缘或配饰的少量重合允许存在。
3. **Given** 狗狗被缩小以避免遮挡，**When** 查看任一必要动作、卡片或预览，**Then** 全身动作不被裁切，落点仍与目标格一致。
4. **Given** 用户已上传三只狗的新动作表，**When** 制作两种狗狗外观，**Then** 各角色使用对应身份的原表，原件得到保留；若某个动作表未通过素材检查，该外观不能作为已完成版本交付。

### User Story 3 - 对局运行流畅 (Priority: P1)

玩家在普通对局与角色、投射物较多的场景中，看到连续稳定的运动，并能及时完成拖放、铲除和收集操作。

**Why this priority**: 用户报告当前游戏“十分卡顿”，需要测量并改善实际画面呈现及输入响应。

**Independent Test**: 在用户当前电脑的真实显示窗口运行打包游戏；标准场景固定为5向日葵、5豌豆射手、5僵尸、10投射物、3阳光、5割草机，压力场景固定为45植物、30僵尸、100投射物、20阳光、5割草机。两场景各记录连续60秒画面间隔、帧率，并完成20次玩家操作延迟测量，对照改进前数据。

**Acceptance Scenarios**:

1. **Given** 正常对局，**When** 连续游玩60秒，**Then** 角色移动和动作连续，平均画面帧率达到55 FPS，95%的画面间隔不超过33毫秒。
2. **Given** 固定压力场景，**When** 连续运行60秒，**Then** 95%的画面间隔不超过33毫秒，且不出现连续3帧以上、每帧超过50毫秒的可见停顿。
3. **Given** 玩家执行拖放、铲除及收集操作，**When** 游戏处于标准或压力场景，**Then** 20次操作均被正确处理，95%的可见反馈延迟不超过100毫秒。
4. **Given** 画面性能得到改善，**When** 重放相同输入，**Then** 游戏规则、动画既定节奏、火爆辣椒效果时长和胜负结果与现有规格一致。

### Edge Cases

- 背景原图虽大，但实际细节或授权不足时，不得仅凭像素尺寸判定为合格。
- 在窗口缩放、全屏/窗口切换与暂停恢复后，背景不得失真，角色落点和输入命中位置仍一致。
- 新照片可能有不同裁切、比例、方向或背景；任一照片不可用时，不能把其他狗的身份误用到该角色。
- 密集摆放时允许耳朵、尾巴、配饰边缘轻微相交；相邻角色头部须可辨，主体遮挡不得超过四分之一。遮挡率以每帧透明度至少96的角色像素为主体掩码，排除单独的火焰/光效层；对相邻两只角色取重叠像素数除以面积较小的主体掩码像素数，并检查所有必需动作的最大值。
- 帧率改善不得通过跳过玩法模拟、明显丢弃动作姿势或改变攻击/移动速度获得。

## Requirements

### Functional Requirements

- **FR-001**: 游戏 MUST 使用比现有背景更清晰的新背景，保留当前草坪的房屋、道路和种植格布局，并在1050×600至1920×1080窗口范围内保持清晰、不变形及交互区域可读。
- **FR-002**: 新背景 MUST 可离线使用，并记录可核查的来源、作者、许可及必要署名；仅在许可允许本项目使用时采用。
- **FR-003**: 小宝和小杜 MUST 根据用户重新提供的照片更新外观；好孩子 MUST 根据用户提供的照片替换黄黄，成为狗狗外观中的豌豆射手，且与其他狗可区分。
- **FR-004**: 狗狗外观 MUST 统一控制草坪、拖动、卡片及预览中的角色尺寸，保证全身和必要动作完整可见、落点稳定。
- **FR-005**: 相邻格及相邻行的植物 MUST 保持头部和主要身体轮廓清晰；允许边缘轻微重合，但按本规格 Edge Cases 的主体掩码口径测得的最坏姿态遮挡率不得超过25%。
- **FR-006**: 游戏 MUST 保持既定玩法更新速度与动作节奏，同时改善真实显示窗口中的画面帧率、帧间稳定性和操作反馈。
- **FR-007**: 游戏 MUST 在用户当前电脑运行的打包版本中，提供上述固定标准与压力场景的可重复性能验收结果，并记录设备、窗口尺寸、场景负载及测量时长。
- **FR-008**: 背景和狗狗外观调整 MUST 不改变种植、阳光、伤害、僵尸推进、清行、暂停及胜负规则。
- **FR-009**: 玩家 MUST 能在进入对局前选择狗狗照片版或依据照片生成的卡通版；两版均覆盖小宝、小杜和好孩子，并保持相同的角色映射与玩法规则。
- **FR-010**: 照片版和卡通版 MUST 均完整呈现各角色适用的待机、攻击、受击及结束等动作，保持既定动画节奏及规则结算时间。
- **FR-011**: 照片版中，被窝和嗷嗷嗷 MUST 沿用现有卡通造型；被窝 MUST 使用 `assets/skins/dogs/source/beiwo-sheet.png` 中的初始灰白毛造型。该源表已有金色围巾，保留围巾不影响灰白毛要求。

### Key Entities

- **背景素材**：展示草坪的图像及其来源、许可、可见细节和目标画面范围。
- **狗狗参考照片**：用户提供并标注身份的原始图像，用于核对角色外观特征。
- **狗狗角色外观**：照片版或卡通版、狗狗身份、对应游戏角色、动作和在各显示位置的可见边界。
- **性能测量场景**：可复现的对局负载、窗口尺寸、测量时长及画面/操作指标。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 三种目标窗口尺寸的同场景新旧截图均完成原始像素尺寸并排检查；房屋边缘、草坪格线、道路纹理和角色对比度四项在每种尺寸下均记录为通过，无可见块状模糊、拉伸或断裂；新背景来源及许可记录完整。
- **SC-002**: 收到照片后，玩家可在进入对局前选择照片版或卡通版；两版中三只狗均可由用户通过外观辨认，所有必要动作主体无裁切，最大姿态下相邻植物主体遮挡不超过25%。
- **SC-003**: 用户当前电脑运行的打包游戏在真实显示窗口中，标准场景连续60秒平均至少55 FPS；标准与固定压力场景的95%画面间隔均不超过33毫秒。
- **SC-004**: 20次拖放、铲除或阳光收集操作正确完成，95%可见反馈延迟不超过100毫秒。
- **SC-005**: 固定输入重放的玩法结果与改进前一致；原有12–18姿势/秒动作要求及小杜2秒清行表现保持成立。

## Assumptions

- 本轮“卡顿”指实际游戏画面的帧率与帧间稳定性问题，需以真实显示窗口测量；此前仅在模拟显示环境获得的约60 FPS结果不能证明用户看到的画面流畅。
- 用户已上传小杜、小宝和好孩子的 10×6 动作表，三张原件保存在 `assets/skins/dogs/source/`，具体文件与哈希见 `docs/validation/dog-source-intake-005.md`。
- 好孩子按用户确认替换黄黄担任豌豆射手；其余现有狗狗与游戏角色映射保留。
- 照片版只要求小宝、小杜和好孩子使用新照片；被窝和嗷嗷嗷沿用卡通造型。被窝使用仓库中的 `assets/skins/dogs/source/beiwo-sheet.png` 灰白毛源表，源表已有金色围巾。
- 背景以可核查授权、足够清晰且适合现有草坪布局为选择前提。初步联网候选包括 [OpenGameArt 的 CC0 草地背景](https://opengameart.org/content/grassy-plains-background) 与 [CC0 草地纹理](https://lpc.opengameart.org/content/grass-pixel-art)；最终采用前需核对画面适配及许可。
- 画面目标沿用现有60 FPS、60Hz玩法更新要求；性能验收设备为用户当前电脑，硬件与驱动信息应随打包游戏的测试结果一起记录。
