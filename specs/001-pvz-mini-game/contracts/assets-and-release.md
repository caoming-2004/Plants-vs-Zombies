# Assets and Release Contract

## 动画与参考

assets/skins/{skin_id}/manifest.json使用data-model.md定义的版本1格式。
PNG图集+JSON时间轴，允许在素材制作时使用分层骨骼工具，但运行时预烘焙为图集，首版不引入骨骼运行库。
所有角色逐状态列出方向、帧时长、循环、脚底锚点和发射/接触锚点，裁切帧必须保留原始画布偏移。小狗idle/walk/produce/attack/bite等重复循环总时长至少60 tick；hit/die等一次性动作不受循环时长下限约束。动画表现至少30Hz采样、绘制目标60 FPS，且不得改变固定60 tick/s的权威模拟。
受击可为叠加闪烁，不得每次受击重置攻击周期；死亡动画播放完后销毁表现对象，即使逻辑对象早已移除。

默认动作矩阵：向日葵idle/produce/hit/die；射手idle/attack/hit/die；僵尸walk/bite/hit/die。
附加素材：卡片、阳光、豌豆、草坪、菜单、铲子状态、割草机待命/清扫及离场。
小狗保留三角色矩阵，铲子与割草机保持默认外观。小狗通过角色标识、朝向和姿态区分双方，不改变碰撞边界。每个角色相对对应默认角色等比缩放，高度不低于75%。将三种角色的全部两两组合（含同角色配对）置于同一行相邻列格子中心，逐帧检查所有动作状态的非透明可见像素；依据source_size、trim_offset及脚底锚点还原实际绘制位置后，轮廓像素不得相交，同时保持动作锚点与脚底连续。

制作前建立docs/art/reference-board.md：PC初代经典版版本说明、界面与各动作截图/视频时间段、尺寸/节奏对照。
建立docs/art/dog-mapping.md：每个角色的具名小狗参考、候选映射及拟定动作；用户确认后记录确认日期与内容。
不以图片搜索标签自动断定身份，不在当前规划中虚构具体小狗的长相或已取得素材。

validate_assets工具检查清单引用、图片边界、帧时长、动作覆盖、锚点与默认回退；同时对所有狗狗角色组合逐帧比较相邻列格子中心布局下的非透明像素遮罩，若发现交叠须报告角色、动作及帧编号。
preview_animations工具提供全部动作与状态切换的隔离预览和截图导出；至少3循环及所有适用过渡人工检查。
仅格式校验不能证明原版一致性或具名小狗相似度，需对照板逐项人工验收。

## 视觉验收尺度

战斗以1050×600逻辑画布测量，窗口缩放后的物理像素不作为角色锚点误差单位；PC初代参考截图按已记录的共同比例映射到此画布坐标，界面为加长地图新增的横向区域作为明确的项目布局差异记录。
制作前在参考板固定每个对照项的来源、参考截图/时间段和测量值；无可测参考则标NOT_RUN，不能自行判PASS。
原版对照采用以下可重复检查，数值为本项目验收容差，不声称是原版公开参数：

- 静态布局：草坪、卡槽、资源区及按钮边界位置与参考偏差各不超过2逻辑像素；只比较本规格范围内的元素，中文文案及仅两卡片按已明确差异记录。
- 角色比例：对齐相同关键姿态后，可见轮廓包围盒宽高与参考各相差不超过5%；待机、发力、收回、行走接地、啃咬接触和死亡终态均留图对照。
- 节奏：默认外观完整动作周期与参考相差不超过5%且至少允许1模拟tick的采样误差；动作顺序、朝向和关键姿态不得缺失。美术周期与玩法周期不一致时通过表现映射处理，不能修改伤害/产出数值凑帧。
- 连续性：扣除模拟位置移动后，所有循环接缝和状态转换的世界脚底锚点跳变不超过1逻辑像素；统一角色缩放不得在转换时改变。此项同时用于默认及小狗皮肤。
- 小狗尺度与间距：角色高度至少为对应默认角色的75%；逐一测试三种角色的全部两两组合（含同角色配对），将两角色放在同一行相邻列格子中心，对所有动作帧成对检查非透明像素遮罩，依据裁切偏移及脚底锚点还原后不得有像素相交。缩放以统一锚点为基准，不改变碰撞、射程、占格或玩法数值。
- 小狗节奏：每种重复动画循环时长至少60模拟tick；动画采样至少30Hz，窗口绘制目标60 FPS。通过固定窗口视频/逐帧预览验证更新连续、无跳帧感；一次性受击/死亡不套用循环时长门槛。
- HUD层级：覆盖高密度角色和场上阳光靠近右上区域两种场景，阳光图标/数字完整可见；对图像边界及点击范围均检查无重叠，HUD操作不得误触发收集。
- 同步：发射、产出或啃咬关键视觉帧与对应模拟事件相差不超过1tick，发射/接触位置与约定锚点相差不超过2逻辑像素。
- 每项保存参考、实际帧/录像、测量结果和审核结论；每个适用动作至少3循环并覆盖所有适用过渡。默认造型及关键姿态由项目维护者逐项审核，小狗按已确认身份与映射审核；数值合格不能替代造型审核。

## Windows发行

在Windows x64用项目独立Python3.12构建，PyInstaller onedir+windowed，入口为独立启动脚本，调用pvz_game.app。
packaging/pvz_game.spec将src加入pathex，收集pygame依赖、assets及字体；布局以构建后验证结果记录。
默认PyInstaller支持目录放在_internal；资源使用模块__file__相对定位并验证真实布局，不依赖启动工作目录。
发行根目录含游戏exe、_internal资源依赖目录和《开始游戏.txt》；整体压缩，不制作安装器、不要求单文件。
开发者用requirements.lock.txt记录Windows/Python版本及精确依赖，先构建调试版检查错误，再构建无控制台发行版。

启动说明明确：完整解压、双击exe、保留全部资源、整体移动目录、基础操作、缺文件重新解压。
包含中文字体且附来源信息；不依赖玩家机器已安装某种字体。
错误显示中文提示；详细日志写入LOCALAPPDATA/PvzMiniGame/logs，目录不可写时仍显示错误，不向游戏目录强制写文件。
不联网、不遥测；日志不记录用户名或完整用户路径，滚动保留最近3份各最多1MB。
