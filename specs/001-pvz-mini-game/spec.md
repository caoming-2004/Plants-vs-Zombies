# Feature Specification: 植物大战僵尸基础小游戏与小狗换肤

**Feature Branch**: `version1`

**Created**: 2026-10-25

**Status**: Requirements revised — existing plan and tasks need synchronization

**Input**: 用户要求面向电脑小白，提供双击运行的 exe；先完成基础玩法并支持后续扩展；界面、植物、僵尸与动作和原版一致，可联网搜索美术参考；植物和僵尸可切换为门头沟“俊良”小狗皮肤，换肤后动作连贯合理。后续修订要求修正右上角阳光显示被图像遮挡、加长地图、缩小狗狗并避免相邻狗狗重叠，以及降低狗狗动作节奏并提高动画流畅度。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 双击启动并完成一局游戏 (Priority: P1)

不懂编程的 Windows 用户获得游戏后，双击明确标识的游戏程序，阅读简短中文提示，
通过鼠标完成收集阳光、种植和抵御僵尸，看到胜负结果并重新开始。

**Why this priority**: 先提供无需开发环境的完整可玩闭环，其他内容在此基础上增量交付。

**Independent Test**: 在未安装开发工具、断网的目标电脑上获取发行包，按随包说明启动，
分别完成一次胜利和失败，再重新开始，验证全流程无需命令行或下载依赖。

**Acceptance Scenarios**:

1. **Given** 用户已获取压缩发行包并按说明解压全部文件，**When** 双击解压目录中的游戏 exe，**Then** 出现中文主界面及开始入口，无需配置路径、安装开发环境或登录。
2. **Given** 首次进入关卡，**When** 用户阅读操作提示并收集阳光、选择植物和点击空格，**Then** 阳光增加或按价格扣除，植物成功放置并执行其职责。
3. **Given** 阳光不足、卡片冷却或格子被占用，**When** 尝试种植，**Then** 显示可理解的失败反馈，不扣费、不覆盖已有植物。
4. **Given** 植物和僵尸在同一路线上，**When** 僵尸进入射程或接触植物，**Then** 射手攻击、僵尸啃咬，双方按规则受伤和移除。
5. **Given** 关卡波次已全部出现，**When** 最后一只僵尸被消灭，**Then** 显示胜利；僵尸触及本行防线时先触发尚未使用的割草机；本行割草机已用尽后，再有僵尸越过防线才显示失败。
6. **Given** 一局已结束，**When** 点击重新开始，**Then** 资源、冷却、单位、波次、每行割草机与结果重置，能够再次游玩。
7. **Given** 游戏正在运行，**When** 暂停并继续，**Then** 暂停期间单位、资源计时、冷却和波次均不推进，恢复后接续原状态。

8. **Given** 场上已有植物，**When** 选择铲子并点击该格，**Then** 植物移除、格子可再次种植，阳光不增加且卡片冷却不重置。
9. **Given** 本行割草机待命，**When** 僵尸触及防线，**Then** 割草机向右清扫接触的僵尸且只使用一次；此后再有僵尸突破本行防线则失败。
10. **Given** 用户进入战斗画面，**When** 查看右上角阳光余额，**Then** 数值与图标清晰可见，任何角色、装饰或界面图像均不遮挡阳光显示。
11. **Given** 用户游玩白天关卡，**When** 查看草坪和两侧边界，**Then** 可见五行十二列的完整可玩地图，横向长度大于原九列布局且格子仍可辨认和操作。

### User Story 2 - 体验与参考原版一致的界面及动作 (Priority: P2)

熟悉原版的玩家能认出草坪、卡槽、阳光、植物和僵尸，并从动画中清楚辨认待机、产出、
攻击、行走、啃咬、受击和死亡等行为。

**Why this priority**: 原版视觉与动作一致性是明确的产品要求，完整首版交付必须满足。

**Independent Test**: 将未换肤的同一场景与确认的参考版本逐项对照，覆盖界面、角色外形和全部适用动作；
本故事在基础战斗可用后独立验收，不依赖小狗皮肤。

**Acceptance Scenarios**:

1. **Given** 已确认参考版本，**When** 展示主界面和战斗画面，**Then** 草坪布局、卡槽、资源显示、角色造型及相对比例符合参考对照项。
2. **Given** 原版外观正在播放，**When** 在待机、攻击、行走、啃咬、受击和死亡间切换，**Then** 动作方向、节奏及关键姿态与确认参考一致，无缺帧闪白或错位。
3. **Given** 动画与战斗同时进行，**When** 发射或发生啃咬，**Then** 发射位置、接触位置和伤害发生时刻与可见动作一致。
4. **Given** 战斗画面正在显示阳光余额，**When** 角色或装饰图像出现于右上区域，**Then** 阳光图标和数值仍完整可见且无遮挡。

---

### User Story 3 - 为双方切换小狗皮肤并保持完整动作 (Priority: P3)

玩家在开始一局前为植物方与僵尸方分别选择默认外观或小狗外观，在预览和实战中观察连续动作，
仍能判断角色阵营、职责与当前状态。

**Why this priority**: 这是首版需要交付的特色功能，在基础闭环与参考视觉完成后实施；优先级不代表移出首版。

**Independent Test**: 对每一种首版角色，分别验证默认和小狗外观，以及只换植物、只换僵尸、双方都换三种组合，
每种组合都能完成游戏；使用相同输入和出怪安排核对换肤前后的战斗结果。

**Acceptance Scenarios**:

1. **Given** 已进入外观选择，**When** 分别切换两方外观，**Then** 显示名称与预览，角色映射清楚，双方选择互不覆盖。
2. **Given** 小狗外观被选中，**When** 开始游戏，**Then** 对应卡片、预览和场上角色外观一致，同时保留可辨认的阵营和职责提示。
3. **Given** 小狗角色待机或行走，**When** 转入产出、攻击、啃咬、受击或死亡，**Then** 身体朝向、落脚点与比例连续，动作符合小狗身体结构和角色职责，无静态图片瞬移或仅用整图抖动代替动作。
4. **Given** 换肤前后规则及操作相同，**When** 完成同一局，**Then** 价格、冷却、生命、伤害、移动速度和胜负结果不因外观改变。
5. **Given** 某皮肤缺少必要动作或无法载入，**When** 预览或应用，**Then** 显示中文提示并使用完整默认外观，不导致崩溃或角色消失。
6. **Given** 同一行有相邻列格子中心的两只小狗角色，**When** 检查三种角色的全部两两组合（含同角色配对）和所有动画帧，**Then** 依据裁切偏移与脚底锚点还原后的非透明像素不相交，且狗狗角色高度不少于对应默认角色高度的75%。
7. **Given** 小狗角色重复待机、行走、产出、攻击或啃咬，**When** 观察完整动画循环，**Then** 各循环不少于 1 秒，姿态变化连续流畅且不出现跳帧感；受击和死亡等一次性动作不受该循环时长下限约束。

### Edge Cases

- 中文、空格路径及标准用户权限下启动；缺少必要基础资源时显示明确错误，不出现无提示退出。
- 快速连点卡片、重复点击同格、点击草坪外部和取消种植，不重复扣费或生成重叠植物。
- 同一时刻先处理伤害、死亡与可用割草机救场，再判断仍存活僵尸是否越过已无救场能力的防线；若成立则失败优先于胜利，结算仅触发一次。
- 游戏结束后继续点击场地不改变结算；反复重新开始不保留上局单位、阳光或计时。
- 暂停时不能收集、种植、铲除或推进战斗（包括割草机）；切换窗口后仍可恢复操作。
- 铲子点击空格不扣费、不改变状态；铲除取消当前植物后不返还阳光，且不重置卡片冷却；取消铲子选择不移除植物。
- 同一行多只僵尸同时触发防线只消耗一台割草机；割草机从左向右清除沿途接触的僵尸，通过右边界后离场，不为以后生成的僵尸保留清除效果。
- 默认与小狗外观在循环衔接、动作中断和死亡移除时不闪烁、不突然改变大小或脚底位置。
- 为避免战斗中切换造成状态歧义，首版仅在开局前切换；重新开始保留本次会话的外观选择。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 必须以压缩包交付 Windows exe、完整资源及中文启动说明；用户解压全部文件后双击 exe 即可进入中文界面，无需开发工具、命令行、管理员权限或首次联网下载。说明必须明确不可单独移走 exe，移动游戏时须保留整个解压目录的结构。
- **FR-002**: 必须提供开始、简短操作说明、暂停/继续、重新开始、铲子和退出入口，以鼠标为主要操作方式。
- **FR-003**: 首版必须提供一个白天草坪关卡，范围为五行十二列；完整地图必须在同一画面中可见，必要时加宽游戏窗口，不以横向滚动或缩小格子来容纳地图，且格子仍须清楚可辨和操作。受支持窗口的客户区不得小于1050×600逻辑像素；窗口不得缩小到该下限以下。关卡包含固定且有限的出怪波次及可达成的胜利条件。
- **FR-004**: 首版必须包含向日葵、豌豆射手和普通僵尸，提供资源生产、远程防御与进攻行为。
- **FR-005**: 必须支持自然掉落及向日葵产出阳光、点击收集、显示余额、按价格种植和种植冷却；具体平衡数值在后续设计中集中定义并保持一致。
- **FR-006**: 必须校验格子、阳光和冷却，允许取消选择；失败操作不扣资源、不覆盖植物，反馈说明原因。
- **FR-007**: 豌豆射手必须攻击同一行前方有效僵尸；僵尸接触植物后停止前进并啃咬，目标消失后继续前进；生命耗尽的单位停止产生战斗效果并移除。
- **FR-008**: 必须展示胜负并阻止结算后的场地操作；波次全部出现且场上无存活僵尸时胜利；僵尸越过已无可用割草机的本行防线时失败。重新开始必须重置整局状态，包括每行割草机，保留本次会话的外观选择。
- **FR-009**: 默认界面、植物、僵尸与适用动作必须以 PC 初代经典版为验收基准，不得自行降级为近似风格；范围限于本规格列出的首版内容。
- **FR-010**: 默认角色必须覆盖其全部适用动作：植物待机、产出或攻击、受击、死亡；僵尸行走、啃咬、受击、死亡。原版通过闪烁等方式表达的受击也属于可对照动作反馈。
- **FR-011**: 必须允许植物方和僵尸方在开局前独立选择默认或小狗皮肤，至少提供每个首版角色的一套完整小狗外观，并同步卡片和预览。
- **FR-012**: 小狗皮肤对象确认为骏良的门头沟小狗群体。由开发方依据可追溯参考挑选小狗，提出向日葵、豌豆射手、普通僵尸的对应方案，并附名称、外观参考和动作适配说明供用户确认；用户确认映射后才开始相应皮肤的正式制作，不得擅自以任意犬种替代。
- **FR-013**: 小狗外观必须覆盖 FR-010 的对应行为，体现可辨认的头部、躯干或肢体动作；状态过渡保持朝向、比例和落脚点连续，发射点及接触点与行为匹配。
- **FR-014**: 换肤必须仅改变外观，不改变数值、占格、有效攻击范围或胜负规则；皮肤不完整时提示并回退默认外观。
- **FR-015**: 必须随发行包提供全部运行所需资源；在线搜索用于准备参考和素材，不得成为玩家运行时的依赖。采用的视觉参考与素材必须可追溯到来源及对应角色/动作。
- **FR-016**: 后续增加植物、僵尸、关卡或皮肤时，必须保留已有可玩流程及既有外观组合；新增内容与平衡调整须有明确验收范围。
- **FR-017**: 必须验证资源增减、种植限制、攻击与啃咬、胜负、暂停及重开，并对两种外观验证关键动作和完整对局；记录实际结果，不将未执行检查视为通过。

- **FR-018**: 必须提供铲子选择、取消和点击格子铲除植物的操作；铲除立即移除目标并停止其后续产出或攻击，不返还阳光、不重置卡片冷却；空格操作不产生效果，暂停和结算后不得铲除。
- **FR-019**: 每行开局必须有一台一次性割草机；存活僵尸触及本行防线时自动触发，向右清除沿途接触的僵尸后离场；不会影响其他行，每局每行最多触发一次。无可用割草机时僵尸越过本行防线即失败；重开恢复全部割草机。默认外观的铲子、割草机及其动作均纳入 PC 初代经典版视觉对照，首版不对这两项换小狗皮肤。
- **FR-020**: 阳光图标及余额必须固定显示在画面右上角的可读区域；任何角色、场景、装饰或其他界面图像均不得覆盖或遮挡其图标、数值或点击区域。
- **FR-021**: 小狗皮肤的每个角色必须按比例缩放并适配其所在位置；将三种角色的全部两两组合（含同角色配对）置于同一行相邻列的格子中心时，所有动画帧中非透明可见像素均不得相交。轮廓比较须依据帧裁切偏移和脚底锚点还原后的实际绘制位置，且角色高度不得小于对应默认角色高度的75%，保证彼此分明且仍清楚可辨。
- **FR-022**: 小狗的待机、行走、产出、攻击和啃咬等重复动画循环必须舒缓，每个完整循环不得短于 1 秒；受击、死亡等一次性动作不受该时长下限约束。播放时须保持至少 30 次/秒的动画画面更新，并以 60 帧/秒为目标绘制，使连续动作流畅、状态转换无突兀跳变。

### Key Entities *(include if feature involves data)*

- **对局**：当前阶段、阳光余额、波次、场上单位、胜负及暂停状态。
- **草坪格子**：行列、可种植状态和占用植物。
- **植物类型与实例**：类型、价格、冷却、生命、产出或攻击能力，以及当前格子和行为。
- **僵尸类型与实例**：生命、移动、啃咬能力、所在行、位置、目标和行为。
- **阳光与投射物**：位置、可收集量或伤害、有效状态。
- **关卡**：草坪范围、出怪安排、结束条件。
- **皮肤与角色映射**：名称、参考对象、适用角色、动作覆盖、预览及素材来源。
- **割草机**：所属行、待命/清扫/已消耗状态和清扫位置；每局每行一台。
- **操作选择**：无选择、所选植物或铲子；三者互斥。
- **会话外观选择**：植物方、僵尸方所选皮肤，在重开时保留。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在没有开发环境的 Windows 10/11 64 位标准用户电脑上，完整解压压缩包后断网双击目录中的 exe 即可进入主界面，无额外安装或配置；两个系统各至少一次实机验证，并验证整个游戏目录移动到含中文和空格的新路径后仍可启动。
- **SC-002**: 至少 3 名未参与开发的电脑新手中，全部可仅依随包中文说明在 3 分钟内开始关卡并成功收集阳光、种下一株植物。
- **SC-003**: 默认外观及三种换肤组合均完成至少一次胜利、一次失败和一次重开，全部符合验收场景，无阻塞操作、崩溃或上局状态残留。
- **SC-004**: 每个首版角色在每套外观下，FR-010 所列适用动作覆盖率为 100%；逐项观察至少三个完整循环及所有适用状态过渡，无缺失或闪白；扣除模拟移动后循环接缝和状态过渡的脚底锚点跳变不超过1个1050×600战斗逻辑画布像素，状态转换不改变角色缩放，关键行为视觉反馈与游戏事件相差不超过1/60秒。
- **SC-005**: 同一输入和出怪安排在默认与换肤外观下至少进行 3 组对照，资源变化、伤害结果及胜负完全一致。
- **SC-006**: 已确认原版的界面、三种角色和适用动作对照项全部经逐项验收通过；小狗外观与确认映射一致，仍可辨认阵营、职责及动作；默认静态元素位置偏差不超过2逻辑像素，同姿态角色宽高偏差各不超过5%，动作周期偏差不超过5%且至少允许1/60秒采样误差；按固定参考逐项留存测量及维护者造型审核结论。
- **SC-008**: 铲除已种植物、铲空格、取消铲子、暂停/结算时铲除、每行割草机首次触发、同一行重复突破、跨行独立触发及重开恢复均有通过的验收记录；不返还阳光且不重置冷却。
- **SC-007**: 持续游玩 30 分钟、暂停/继续和重新开始各至少 10 次后，仍可完成正常对局，无角色消失或操作失效。
