# Implementation Plan: 植物大战僵尸基础小游戏与小狗换肤

**Branch**: `version1`（功能目录标识：`001-pvz-mini-game`） | **Date**: 2026-10-25 | **Spec**: [spec.md](spec.md)

**Input**: `specs/001-pvz-mini-game/spec.md`

## Summary

基于仓库中现有的 Python/pygame-ce 可玩原型迭代，不另建框架。将战斗逻辑画布由
800×600 扩展为 1050×600，保留 72×76 草坪格尺寸，把关卡扩至五行十二列并在同一画面
呈现；初始窗口按 1260×720 等比显示，允许用户调整大小。菜单美术保持原比例并在新画布居中。
重排 HUD 与世界绘制层，阳光余额最后绘制且输入命中优先级高于场上阳光。小狗重复动作
循环至少 60 个模拟 tick，动画至少 30 次/秒采样，窗口绘制目标 60 FPS；模拟仍固定
60 tick/s，不因渲染帧率、动作长度或外观而改变玩法结果。

## Technical Context

**Language/Version**: Python 3.12 x64；通过 uv 使用项目虚拟环境。

**Primary Dependencies**: 现有 pygame-ce 2.x（窗口、输入、绘制、动画）、pytest 8.x
（测试）、PyInstaller 6.x（Windows onedir 发行）；依赖清单已存在，实施时验证并锁定精确版本。

**Storage**: 现有 JSON 配置、关卡与皮肤清单，PNG 图集及随包中文字体；外观选择仅保存在会话内。

**Testing**: pytest 规则与表现集成测试、SDL dummy 冒烟、固定输入回放；通过真实窗口截图/
预览检查地图同屏显示、阳光遮挡、角色最大轮廓与动画循环；Windows 10/11 离线发行实测。

**Target Platform**: Windows 10/11 x64，标准用户、离线、允许含中文和空格的移动目录。

**Project Type**: 已有单进程 2D 桌面游戏，源码位于 `src/pvz_game/`，资源位于 `assets/`。

**Performance Goals**: 战斗逻辑画布 1050×600；首开窗口 1260×720，缩放保持比例。
模拟 60 tick/s、绘制目标 60 FPS、小狗动画采样至少 30 次/s。按规格压力场景
（45 植物、30 僵尸、100 投射物和20阳光，持续60秒）平均不少于55 FPS、95%帧不超过33ms。
资源载入主菜单目标10秒内。

**Constraints**: 五行十二列须完整同屏显示，禁止横向滚动或缩小格子；格子维持72×76逻辑像素。
受支持窗口客户区至少1050×600逻辑像素，窗口不可缩至此下限以下。
右上阳光 HUD 必须不被世界图像遮挡，点击范围优先于世界对象。默认和狗狗外观共享玩法逻辑。
狗狗高度至少为默认对应角色75%；三种角色的全部两两组合（含同角色配对）置于同一行相邻列中心时，全部动作帧的非透明像素轮廓不得相交；重复动作循环
至少60 tick。素材映射未确认前不得将候选小狗当作已批准对象。

**Scale/Scope**: 单个白天关卡、两植物、一种僵尸、每行一台割草机、双方独立选外观；
只在开局前选择，不包含联网、存档、商城、编辑器或自定义皮肤导入。

## Current Codebase and Design

仓库已有可运行源码与测试，而非空白脚手架。主要实施边界：

- `src/pvz_game/config.py` 校验关卡与参数；T007已更新为只接受五行十二列，T029已同步关卡与布局配置。T028至T033已完成列边界、1050×600窗口输入映射、地图绘制及阳光HUD遮挡/命中优先级的实现和自动化验证；原版视觉对照验收仍由T043至T045覆盖。
- `src/pvz_game/domain/` 保持权威模拟、命令和状态；不将视觉坐标或动画回调引入规则层。
- `src/pvz_game/app.py` 建立窗口、逻辑固定步进、画布到窗口的比例缩放及输入坐标映射。
- `src/pvz_game/presentation/renderer.py`、`prototype_renderer.py` 和 `scenes.py` 管理布局、图层与控件；共享 UI 几何由输入和绘制共同使用。
- `src/pvz_game/presentation/animation.py` 消费 tick 与事件播放皮肤；扩展按时间采样/平滑切帧但不能更改玩法事件。
- `assets/config/balance.json`、`assets/levels/day_01.json`、`assets/skins/*/manifest.json` 保存显示所需尺寸、关卡范围及动画数据。

## Implementation Stages

- **A — 画布与地图**：扩展战斗逻辑画布与窗口缩放/输入映射；12列整图同屏，保持格子尺寸；
  调整背景边缘、出怪位置、割草机与草坪边界；配置验证和单元/集成测试覆盖有效边界。
- **B — HUD 与图层**：把场景绘制划分为背景/草坪、单位与世界阳光、HUD/控件/提示；
  HUD最后绘制，阳光可点击区优先于场上拾取物；校验右上角在高密度单位与阳光下仍无遮挡。
- **C — 小狗尺寸与动画**：取得并审核小狗动作素材与来源；先向用户提交身份/角色映射并获确认，
  再制作正式皮肤。使用默认角色边界框的75%高度下限及最大姿态进行缩放与间距预览；
  重复动作每循环至少60 tick，动画采样至少30Hz、渲染目标60 FPS；受击/死亡保持一次性反馈，
  不为满足循环时长而拖慢或改变战斗事件。
- **D — 回归与发布**：运行规则、资源、回放、渲染和资产完整性验证；四种外观组合进行胜败/
  重开；压力场景、30分钟稳定性、暂停/重开、新手流程及Windows 10/11离线包逐项留证。

## Delivery Dependencies and Risks

- 十二列总宽为864逻辑像素，草坪从x=105开始延伸至x=969；画布加宽到1050可留右侧余量，
  避免移动窗口或缩小格子。客户区小于1050×600逻辑像素的窗口不受支持，窗口最小尺寸须限制在此下限；
  更大窗口可按比例显示，最低支持尺寸下按逻辑画布1:1显示并实测可操作性。
- 背景参考素材原始横向比例不同于新画布；扩展应通过可延展草坪区域和侧边装饰补足，
  不拉伸角色或阳光 HUD；记录与原版明确布局不同的范围。
- 场上阳光可能与 HUD 同处右侧屏幕区域。除最终绘制覆盖之外，输入解析必须保留明确层级，
  不能让 HUD 点击意外收集或遮挡下方场地的游戏对象。
- 当前狗狗图集需检查所有重复循环时长和最宽动画外框；不能只缩小待机帧而忽略攻击/啃咬帧。
- Windows目标机器及三名新手不一定可用；未执行的实际验收标为NOT_RUN，不用开发机冒充。
