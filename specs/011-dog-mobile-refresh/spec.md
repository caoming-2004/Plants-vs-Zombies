# Feature Specification: 狗狗素材修复与安卓可玩版本

**Feature Branch**: `011-dog-mobile-refresh`

**Created**: 2026-10-30

**Status**: Draft

**Input**: User description: 从原图重新截取被窝和嗷嗷嗷的图片，避免腿部缺失；将胖宝宝的职责从土豆雷调整为倭瓜；构建可在安卓手机直接运行的版本，并隔离 Windows 与 Android 平台专属文件。

- Q: 你希望安卓版最低支持哪个 Android 系统版本？ → A: 魅族 20，以该机型作为安卓安装与运行验收目标。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 完整显示狗狗动作素材 (Priority: P1)

玩家在菜单、卡片和地图中看到被窝与嗷嗷嗷的完整形象和动作，不再出现腿、脚或尾巴被错误裁掉的情况。动作帧来自项目内的原始高清图集。

**Why this priority**: 被裁掉的肢体会直接破坏角色观感；重做裁切是这次视觉修复的核心。

**Independent Test**: 逐帧播放两只狗的现有动作，并在菜单、卡片和地图尺寸下检查每帧轮廓；所有肢体和尾巴都完整可见。

**Acceptance Scenarios**:

1. **Given** 被窝或嗷嗷嗷处于任一可见动作帧，**When** 玩家在菜单、卡片或地图中查看，**Then** 狗的身体、四肢、脚掌和尾巴均完整显示，边缘没有非预期裁切。
2. **Given** 从原图集中提取相邻动作帧，**When** 动作连续播放，**Then** 每帧只包含对应的一只狗，透明边缘不带入相邻帧的角色，也不会因边界变化造成肢体忽隐忽现。
3. **Given** 多种狗狗外观同时出现在地图上，**When** 玩家比较其站立状态，**Then** 各外观显示大小接近，允许适度重合，但每只狗的完整轮廓仍在地图可视范围内。

### User Story 2 - 使用胖宝宝作为倭瓜 (Priority: P1)

玩家选择胖宝宝时，看到并使用的是倭瓜职责：它会对附近目标进行一次重击并在攻击后消耗，不再像土豆雷一样埋地等待僵尸触发。

**Why this priority**: 胖宝宝的职责变化会影响选择卡片、战斗反馈和已有对局策略，必须和外观名称一致。

**Independent Test**: 在一局游戏中选择并放置胖宝宝，观察卡片身份、部署状态、攻击和消耗过程；确认它不进入埋地待机或接触触发流程。

**Acceptance Scenarios**:

1. **Given** 玩家在狗狗外观选择中选择胖宝宝，**When** 进入关卡，**Then** 胖宝宝仍以独立狗狗外观选项出现，并绑定倭瓜职责，不覆盖其他植物的职责或外观。
2. **Given** 胖宝宝被放置且附近有可攻击僵尸，**When** 攻击条件满足，**Then** 胖宝宝完成一次近距离重击并被消耗。
3. **Given** 胖宝宝已经放置且攻击条件尚未满足，**When** 僵尸接近，**Then** 胖宝宝不会按土豆雷机制埋地待机或等待踩踏触发。

### User Story 3 - 在安卓手机直接游玩 (Priority: P1)

玩家可在安卓手机上安装并启动游戏，通过触屏完成选择植物、布置防线、收集资源、暂停和结束一局游戏的主要操作，不需要在手机上安装开发工具或连接电脑。

**Why this priority**: 可在手机直接运行是本次明确要求的交付结果；仅能在桌面运行不足以交付。

**Independent Test**: 将可安装的 Android 应用包传到魅族 20 并离线安装启动；只用触屏完成一次完整对局流程，并检查地图和控件显示。

**Acceptance Scenarios**:

1. **Given** 玩家拿到游戏安装包，**When** 在魅族 20 上安装并启动，**Then** 无需电脑或开发工具即可进入游戏，游戏资源随安装包提供，核心对局可离线运行。
2. **Given** 玩家进入关卡，**When** 使用触屏点击卡片或拖动角色并松开，**Then** 角色落到松开位置最近的有效格子；若该格已被占用，则提示操作未完成且不自动改种到其他格子。
3. **Given** 玩家通过触屏进行主菜单、暂停、继续、结束和重新开始操作，**When** 点击对应控件，**Then** 界面及时响应且不要求键盘或鼠标。
4. **Given** 安卓手机处于横屏且屏幕比例不同，**When** 显示关卡界面，**Then** 全部地图行列、必要状态信息和主要操作控件均可见并可触达，不被屏幕边缘或安全区域裁切。
5. **Given** 植物处于循环动作中，**When** 玩家在魅族 20 上连续观察 10 秒，**Then** 动作节奏约为每秒 12 个不同姿态，不出现明显卡帧；该节奏不代表游戏整体刷新率。

### User Story 4 - 隔离 Windows 与 Android 文件 (Priority: P1)

维护者分别构建 Windows 版和 Android 版时，能清楚区分两端专属的配置、缓存、中间文件和交付包；构建或清理一端不会改动另一端文件。

**Why this priority**: 两个平台的打包环境和交付物不同，文件混放容易导致误覆盖、误删除或错误发布。

**Independent Test**: 分别构建两端并记录各自文件清单及校验值；清理其中一端的临时产物后，确认另一端的配置、缓存和交付物仍存在且内容未变。

**Acceptance Scenarios**:

1. **Given** Windows 与 Android 均有构建或发布文件，**When** 执行 Windows 构建或清理，**Then** Android 专属文件的路径、数量和内容均不变化。
2. **Given** Windows 与 Android 均有构建或发布文件，**When** 执行 Android 构建或清理，**Then** Windows 专属文件的路径、数量和内容均不变化。
3. **Given** 游戏核心代码和素材被两端共同使用，**When** 任一平台打包，**Then** 共同文件保持单一权威副本，平台专属文件仍按各自目录隔离。

## Edge Cases

- 原图中某一帧的狗接近图集边缘时，仍须完整保留轮廓，且不得误取相邻帧的肢体。
- 不同动作姿态的脚掌高度或尾巴位置变化时，帧边界仍须避免显示抖动、截断或突然跳变。
- 胖宝宝攻击范围内没有有效目标时，应继续遵循同一倭瓜职责的等待或失效规则，不得退化为土豆雷机制。
- 触屏拖动经过多个格子后松开时，应按松开点判断最近格；松开点最近的格子被占用时拒绝本次放置。
- 手机屏幕比例、前置摄像头安全区域或系统导航栏遮挡边缘时，主要操作区仍须可见、可触达。
- 游戏切换到后台再返回时，不得丢失当前对局状态或让暂停控件失效。
- 安装包启动时没有网络连接，仍应能进入并完成核心对局。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 从项目内被窝和嗷嗷嗷的原始高清图集中重新划分各动作帧，不得以已经裁切错误的输出帧作为唯一图像来源。
- **FR-002**: 系统 MUST 在被窝和嗷嗷嗷所有展示尺寸及可见动作帧中完整呈现身体、四肢、脚掌和尾巴；帧边缘 MUST 保留足以避免缩放裁切的透明留白。
- **FR-003**: 系统 MUST 保持各角色动作帧的连续性，并使完整角色轮廓在菜单、卡片和地图中均可见。
- **FR-004**: 系统 MUST 维持地图中所有可游玩狗狗外观相近的显示尺度，允许适度重合，但不得因缩放或画面边界导致任何狗狗主体被裁掉。
- **FR-005**: 系统 MUST 将胖宝宝绑定到倭瓜职责，并从胖宝宝的选择卡片和战斗行为中移除土豆雷的埋地待机及踩踏触发行为。
- **FR-006**: 胖宝宝 MUST 在附近存在符合攻击条件的目标时执行一次近距离重击并消耗；其攻击范围、伤害和蓄势时长由关卡平衡规则确定。
- **FR-007**: 系统 MUST 保留胖宝宝与黄黄作为狗狗外观选择中的独立选项，且分别绑定各自职责，不替换或覆盖其他植物的职责。
- **FR-008**: 系统 MUST 提供可在魅族 20 上直接安装和启动的安卓 APK，游戏资源随包提供，核心对局在离线时可用。
- **FR-009**: 安卓版 MUST 支持触屏完成主菜单导航、选择卡片、放置角色、收集资源、暂停、继续、结束和重新开始等核心操作。
- **FR-010**: 安卓版 MUST 支持点击选择和连续触屏拖动放置；拖动松开时按最近格判断落点，最近格被占用时拒绝本次放置且不得自动改放其他格。
- **FR-011**: 安卓版 MUST 在横屏手机的常见屏幕比例和安全区域内完整展示可玩地图、必要状态信息及主要操作控件。
- **FR-012**: 此次安卓版 MUST 保留现有桌面版可玩流程和功能；安卓版交付不要求应用商店上架。
- **FR-013**: 安卓版 MUST 沿用植物动作每秒约 12 个不同姿态的节奏；此要求不改变游戏整体刷新率或玩法更新频率。
- **FR-014**: Windows 与 Android 专属的启动入口、打包配置、构建依赖环境、缓存、中间产物、运行日志和最终发行文件 MUST 分别存放于各自的平台目录；任一平台的构建或清理 MUST NOT 覆盖、修改或删除另一平台目录中的文件。完全共用的游戏核心代码和原始素材保持单一共享副本。
- **FR-014**: Windows 与 Android 专属的启动入口、打包配置、构建依赖环境、缓存、中间产物、运行日志和最终发行文件 MUST 分别存放于各自的平台目录；任一平台的构建或清理 MUST NOT 覆盖、修改或删除另一平台目录中的文件。完全共用的游戏核心代码和原始素材保持单一共享副本。

### Key Entities

- **狗狗动作图集**: 项目中的原始高清狗狗动作图像及其逐帧边界、动作姿势和透明留白。
- **胖宝宝角色**: 独立狗狗外观选项，职责为倭瓜的一次性近距离重击。
- **安卓对局**: 玩家通过手机触屏进行的完整核心关卡流程，包含菜单进入、游戏操作、暂停及结束或重开。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 被窝和嗷嗷嗷的 100% 可见动作帧在菜单、卡片及地图验收尺寸下均完整展示身体、四肢、脚掌和尾巴，非预期裁切数量为 0。
- **SC-002**: 所有可游玩狗狗外观在地图站立状态下的显示高度差异不超过最大显示高度的 20%；任意狗狗的可见主体均不被地图边缘裁切。
- **SC-003**: 在一局对局中，胖宝宝能完成一次近距离倭瓜重击并消耗；重复验证时不会出现埋地等待或踩踏触发行为。
- **SC-004**: 玩家无需连接电脑或安装开发工具，即可在魅族 20 上从交付的安卓应用包安装并启动游戏。
- **SC-005**: 仅使用触屏即可完成进入关卡、至少一次角色放置、收集资源、暂停和继续，并到达该局结束及重新开始流程。
- **SC-006**: 在 16:9 与 20:9 横屏显示比例下，地图各行列及主要操作控件均完整可见、可触达。
- **SC-007**: 游戏在断网状态下可启动并完成一局核心关卡；桌面版仍可进入并完成一局核心关卡。
- **SC-008**: 在魅族 20 上连续观察 10 秒，植物循环动作呈现约 12 个不同姿态/秒，且没有明显卡帧或长时间静止。
- **SC-009**: 分别构建并清理 Windows 与 Android 产物后，另一平台所有专属文件均保持原路径与原校验值；跨平台误覆盖或误删除数量为 0。
- **SC-009**: 分别构建并清理 Windows 与 Android 产物后，另一平台所有专属文件均保持原路径与原校验值；跨平台误覆盖或误删除数量为 0。

## Assumptions

- 本次沿用项目内已有的被窝、嗷嗷嗷原始高清图集及既有关卡；不要求重新生成狗狗造型或增加新关卡。
- “直接运行安卓版本”指交付可由玩家侧载安装的安卓应用包；本次不包含应用商店发布。
- 安卓版以横屏、触屏为主要使用方式；魅族 20 是本次确定的安装和运行验收机型，不额外承诺其他机型的兼容范围。
- 安卓版沿用现有植物动作每秒约 12 个不同姿态的节奏，游戏整体刷新率与玩法更新频率保持独立。
- “Windows 与 Android 文件隔离”指两端的平台专属入口、依赖、配置、缓存、日志、临时文件及发行物分目录管理；完全共用的玩法代码与素材保留一份，避免复制维护。
- “Windows 与 Android 文件隔离”指两端的平台专属入口、依赖、配置、缓存、日志、临时文件及发行物分目录管理；完全共用的玩法代码与素材保留一份，避免复制维护。
- 胖宝宝按倭瓜常见的一次性近距离重击职责理解；伤害和目标距离属于关卡平衡参数，不改变该角色不再是埋地触发植物的职责。
- 本次改动在现有桌面版基础上扩展安卓版，不移除桌面版；其他玩法和角色规则按既有版本保持。
