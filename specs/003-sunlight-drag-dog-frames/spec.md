# Feature Specification: 阳光界面、拖铲操作与小狗动作素材

**Feature Branch**: `version1`

**Created**: 2026-10-26

**Status**: Draft

**Input**: 用户要求：将阳光显示移到左上角；改善种植和铲除植物时的操作手感，支持拖动种植；小宝和小杜形象使用用户提供的60帧图片。

## Clarifications

### Session 2026-10-26

- Q: 你希望怎样把小宝和小杜各自的60帧图片提供给项目？ → A: 用户将在当前对话上传小宝和小杜的素材；逐帧图或合成图均可。
- Q: 你希望铲除植物也支持把铲子拖到植物上释放吗？ → A: 支持铲子拖放并保留原有点击铲除方式。
- Q: SC-004 的拖动预览 P95 应按哪种条件验收？ → A: Windows 60Hz设备、1260×720真实窗口、普通对局至少200个拖动中的实际鼠标移动样本；从程序取出事件计时到首次显示包含新预览的画面。

## User Scenarios & Testing

### User Story 1 - 在左上角查看阳光余额 (Priority: P1)

玩家进入对局后能在画面左上角快速看到当前阳光数量，并在收集阳光、种植植物、暂停和恢复后看到正确的余额。余额显示与场上可点击收集的阳光区分清楚。

**Why this priority**: 阳光决定玩家当前能否种植；把余额放在视线容易找到的位置，可减少新玩家寻找资源和误判可用植物的时间。

**Independent Test**: 启动一局，分别收集阳光、成功种植和尝试资源不足的种植，并在暂停/恢复前后核对左上角余额与实际可用资源一致。

**Acceptance Scenarios**:

1. **Given** 玩家处于对局中，**When** 游戏画面显示，**Then** 阳光余额位于左上角且在受支持窗口大小下均可完整辨认。
2. **Given** 玩家收集阳光或成功种植，**When** 资源发生增减，**Then** 左上角余额及时显示最新数值，场上可收集阳光仍可单独识别和点击。
3. **Given** 玩家打开暂停界面后继续游戏，**When** 对局恢复，**Then** 阳光余额不被遮挡且与暂停前资源状态一致。

---

### User Story 2 - 顺手拖放植物与铲除植物 (Priority: P1)

玩家可以将植物卡片拖到草坪目标格种植，也可以用铲子指向已有植物并释放来移除；放置预览、目标格和成功/失败反馈随操作及时更新。原有点击选卡再点击草坪、点击铲子再点击植物的操作继续可用。

**Why this priority**: 种植和移除是防线调整的主要操作。直接拖放让玩家更容易把工具与目标对应起来，同时保留熟悉的点击方式，避免操作升级破坏已有习惯。

**Independent Test**: 逐一执行植物卡拖到空格、占用格、草坪外的操作，以及铲子拖到有植物和无植物的格子；再用原点击方式完成种植和铲除。检查落点、反馈、阳光、植物状态和每次操作的结算次数。

**Acceptance Scenarios**:

1. **Given** 植物卡可用且阳光充足，**When** 玩家将其拖至空草坪格并释放，**Then** 植物仅种在释放位置对应的格子，阳光只扣除一次并开始冷却。
2. **Given** 玩家拖动植物卡，**When** 指针经过有效格、占用格、草坪外或界面区域，**Then** 有效性预览及时更新并明确区分可放置与不可放置目标。
3. **Given** 玩家把植物卡释放在占用格、草坪外、阳光不足或冷却中的目标，**When** 操作结束，**Then** 不误种、不重复扣费、不改变已有植物，并显示可理解的反馈。
4. **Given** 玩家正在拖动植物卡或铲子，**When** 按取消键/鼠标右键、失去窗口焦点、暂停或结束对局，**Then** 操作被取消，不会在恢复或切换界面后延迟执行。
5. **Given** 玩家把铲子拖到有植物的格子并释放，**When** 铲除有效，**Then** 目标植物被移除一次且不返还阳光；投放到空格或草坪外时不误删其他植物。
6. **Given** 玩家不使用拖动，**When** 通过原有点击方式选择植物后点击空格，或选择铲子后点击植物，**Then** 两种原有流程仍按相同放置和铲除规则完成。

### User Story 3 - 使用小宝和小杜的60帧形象 (Priority: P1)

玩家在选择小狗外观时看到小宝作为坚果墙、小杜作为火爆辣椒；场上角色在待机、受击、职责动作及结束状态中使用对应的用户提供素材，角色身份和动作方向保持连贯。

**Why this priority**: 小宝和小杜是用户指定的角色形象；以用户提供的动画素材为准能保持角色辨识度，并让新增植物外观与场上表现一致。

**Independent Test**: 对小宝和小杜分别检查全部提供帧以及它们在卡片、预览和对局中的对应关系；播放各自适用动作并核对帧序、朝向、位置连续性和皮肤切换后的规则一致性。

**Acceptance Scenarios**:

1. **Given** 玩家选择小狗植物外观，**When** 查看坚果墙与火爆辣椒的卡片、选肤预览和场上角色，**Then** 坚果墙使用小宝形象，火爆辣椒使用小杜形象，三处身份对应一致。
2. **Given** 小宝或小杜执行其适用动作，**When** 动画播放或切换状态，**Then** 使用用户提供的对应帧，帧序、朝向和角色定位连续，不出现突变、错位或错误角色。
3. **Given** 部分动作所需素材缺失或无法读取，**When** 游戏载入小狗外观，**Then** 不崩溃、不将另一个狗狗角色错误替代，并按现有整套默认外观回退规则处理及给出可理解提示。
4. **Given** 玩家使用小狗外观或默认外观，**When** 相同关卡执行相同输入，**Then** 植物规则、资源、战斗结果和胜负状态一致。

### Edge Cases

- 左上角余额不得遮挡植物卡、选卡反馈、对局状态或其他必要交互；窗口缩放和留边区域不得导致余额跑出可视区。
- 阳光余额为0、达到较大数值或资源刚好等于植物价格时，文字仍完整显示且种植校验结果正确。
- 拖动释放在阳光余额区域、植物卡、铲子、暂停按钮或黑边留白处，不得触发目标背后的草坪操作。
- 拖动期间资源变化、目标被占用、对局暂停/结算或窗口失焦时，释放必须按当前对局状态重新校验或取消。
- 铲子拖动到正在受击、已死亡或刚被移除的植物时，不得重复执行移除或影响相邻格。
- 60帧源素材可能是逐帧图片或一个/多个合成图片；顺序、透明边缘、角色尺寸或朝向不符合要求时，必须报告素材问题而不能静默伪造/重复帧。
- 小宝或小杜素材未提供、数量不足或某个动作覆盖不完整时，规格中的素材验收保持未完成；不得把临时占位图描述为用户提供素材。

## Requirements

### Functional Requirements

- **FR-001**: 对局中的阳光余额 MUST 显示在游戏画面左上角，并与草坪上的可收集阳光视觉区分。
- **FR-002**: 左上角阳光显示 MUST 在受支持窗口尺寸、暂停/恢复和阳光增减后保持可见、无遮挡且数值正确。
- **FR-003**: 玩家 MUST 能将四种植物卡拖放到草坪目标格种植，并在拖动期间看到指针位置、目标格和有效/无效反馈。
- **FR-004**: 玩家 MUST 能将铲子拖放到目标植物以移除该植物；有效移除不得返还阳光且仅执行一次。
- **FR-005**: 种植与铲除拖动 MUST 仅在有效目标释放时执行；草坪外、界面控件、无效格、取消、失焦、暂停和结束状态不得导致误放、误删或延迟执行。
- **FR-006**: 拖动种植 MUST 使用当前对局的权威阳光、冷却和占格状态重新验证；成功只扣费、占格和开始冷却一次，失败不改变这些状态并给出明确反馈。
- **FR-007**: 系统 MUST 保留现有点击选卡后点击草坪种植及选择铲子后点击植物移除两种操作，且点击和拖动采用相同的游戏规则。
- **FR-008**: 小狗外观的坚果墙 MUST 使用小宝角色，火爆辣椒 MUST 使用小杜角色；卡片、选肤预览和对局中的对应关系一致。
- **FR-009**: 小宝和小杜的角色动作 MUST 使用用户提供的60帧图像素材，不得用重复姿势补足帧数，也不得用另一角色素材替代；具体可用帧按素材来源角色、动作和方向正确归类。
- **FR-010**: 小宝和小杜素材 MUST 在各自适用动作切换时保持角色身份、朝向、大小和锚点连续；缺少或损坏素材须按既有整套默认外观回退，并提示玩家。作为对既有 `specs/002-animations-plants/spec.md` FR-010 的兼容要求，关键动作还 MUST 至少有24个不同可见姿势/秒；循环clip MUST 至少持续60个模拟tick。
- **FR-011**: 使用不同外观时，植物价格、冷却、生命、伤害、资源结算、对局时序与胜负结果 MUST 保持不变。
- **FR-012**: 本次改动 MUST 保持完整可玩循环以及阳光收集、四种植物、拖动/点击种植、铲除、割草机、暂停、胜负、重新开始和双方换肤可运行。

### Key Entities

- **阳光余额显示**：玩家当前可用资源的可视数值；与草坪中可点击收集的阳光实体不同。
- **拖动操作**：当前工具（植物卡或铲子）、指针位置、目标格、目标有效性和取消状态；成功释放后执行一次对应操作。
- **小狗动画素材**：小宝或小杜的60帧源图像集合，关联角色身份、适用动作、播放顺序、朝向及定位连续性。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 在1050×600、1260×720和1920×1080三种支持尺寸下，阳光余额均完整显示在左上角，无裁切或与卡片/交互控件重叠。
- **SC-002**: 20次预设植物拖放中，有效投放全部落在释放目标格；无效释放和取消操作出现0次误种、错误扣费或重复命令。
- **SC-003**: 20次预设铲子拖放中，有效目标被移除一次且不返还阳光；无效目标和取消操作出现0次误删或误结算。
- **SC-004**: 在Windows 60Hz设备的1260×720真实窗口、普通对局中，采集至少200个拖动中的实际鼠标移动样本；从游戏程序取出每个鼠标移动事件开始计时，到首次显示包含该次更新预览的画面为止，延迟P95不超过50毫秒；拖动操作不发生丢失或重复。
- **SC-005**: 小宝和小杜的用户提供帧均可追溯到对应角色；所有适用动作均通过帧序、角色辨识、方向和位置连续性检查，并满足继承自 `specs/002-animations-plants/spec.md` FR-010 的至少24个不同可见姿势/秒和循环clip至少60个模拟tick门槛；缺失覆盖明确记录为未通过或未执行。
- **SC-006**: 对阳光增减、拖动成功/失败/取消、铲除成功/失败/取消及皮肤选择完成回归后，游戏核心循环及重新开始均正常，且皮肤不改变规则结果。

## Assumptions

- 本特性基于现有 Windows 桌面游戏、1050×600逻辑画布、四张植物卡、既有右上角阳光余额和已有拖动种植/点击铲除操作；本次将余额调整到左上角并改善和扩展拖放反馈。
- 用户已确认植物卡和铲子均支持拖放，同时保留现有点击操作；有效铲除不返还阳光，与现有规则一致。
- “60帧图片”按小宝和小杜各自用于动作的用户提供帧素材理解；不把它解释为游戏必须以60FPS显示，也不限定其为单张拼图还是多张文件，具体素材编排在规划阶段按实际文件确认。
- 本Feature替换小宝/小杜素材时继续遵守 `specs/002-animations-plants/spec.md` FR-010 的既有动作姿势速率要求；动画源帧不能满足时须报告素材缺口，不得降低项目既有验收门槛。
- 用户已确认将在当前对话上传小宝和小杜的60帧素材，逐帧图或合成图均可。素材实际上传前，不以现有生成素材冒充用户提供素材，也不完成依赖该素材的视觉验收。
- 不加入音效、额外植物或新的游戏规则；仅修改阳光显示、玩家操作反馈和小宝/小杜表现素材。
- 发行版继续提供可解压后双击运行的Windows桌面游戏。
