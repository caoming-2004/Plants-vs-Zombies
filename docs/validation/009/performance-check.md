# 界面切换与标准帧时间验收

使用真实 Windows 窗口和 `time.perf_counter()`，将鼠标按下事件注入到事件循环；计时终点是对应目标画面的 `Renderer.draw` 完成并随后第一次 `pygame.display.flip()`。原始十次转换记录见 [transition-check.json](transition-check.json)。

- 开始进入对局（5次）：59.60、44.51、52.58、46.62、42.23 ms。
- 打开换肤页（5次）：54.69、41.70、34.91、33.42、41.50 ms。
- 另测换肤按钮确认（5次）：10.39–16.35 ms，界面立即显示所选项与加载提示；照片图集在后台约568–603 ms就绪后完成实际预览切换，加载期间事件循环继续绘制和接收输入。

基线换肤页首次打开为1.43–1.48秒，原因是绘制菜单时同步解码两套大图集。现改为仅快速检查资源文件并先呈现菜单，随后后台预载；没有在主菜单按钮路径同步解析图集。

最终标准窗口实测见 [window-benchmark.json](window-benchmark.json)：10.014秒、62.31 FPS、P95帧间隔16.01 ms、P95绘制2.864 ms；基线62.26 FPS，保持100.08%。>33 ms帧1次、最长约41.3 ms，无>100 ms帧；60 Hz节奏保持稳定，性能门槛通过。
